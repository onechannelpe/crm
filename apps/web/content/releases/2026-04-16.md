Overview

This PR ships two visible changes (two new field rows: manager and last-updater) and one user
action (inline reassign via a user picker). To deliver those, it also introduces a significant
server-side refactor: the commands/ layer is replaced by a command-api/ + command-kernel/ +
LeadMutationUow pattern that is more explicit about authorization, transactionality, and
dependency injection.

---

What Works Well

LeadMutationUow design is sound. The Unit of Work cleanly encapsulates: transaction scope, patch
derivation, write, event generation, and audit log. inAtomicScope transparently wraps only root
executors, so it composes correctly in nested calls. The new command-api/ handlers are uniform:
prepare → validate → commit, no free-floating effects.

Assignment table design is correct. pipeline_lead_assignments with the partial unique index WHERE
is_active = 1 enforces the single-active-assignment invariant at the DB level. The
replaceActiveAssignment operation inside a transaction makes the constraint safe even under
concurrency.

updatedBy is stamped on all mutation paths. Every command through the new UoW calls
leadWriter.updateLead, which sets updatedBy and updatedAt. The import path also stamps it. The
integration tests verify all three cases (note, reassign, import).

Authorization is layered correctly. prepareLeadCommand checks access before load.
reassignLeadCommand additionally validates scope and isExecutiveAssignable before committing.
listAssignableExecutives also gates on requireLeadAccess.
